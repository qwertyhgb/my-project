# VERSION=V2 — PI-CAI 数据划分与预处理建议

日期：2026-10-13（北京时间）。根据用户要求整理公开资料与本仓库已有证据。

**建议保留全部合格的阳性与阴性病例，通过训练采样处理不平衡；先定位数据处理与模型的具体失败原因，不依据 Dice 或难度删除病例。当前优先保持 Shared A2 与 V2-B/C/D 的数据条件可比较。**

本文是建议材料，不是新的评价协议、实验矩阵或运行状态表。采纳建议前应在相应治理文档中明确范围：
[实验计划](Experiment_Plan.md)、[方法契约](Method.md)、[评价协议](../Evaluation_Protocol.md)。
当前运行状态与历史结果只查阅 [Training Log](../Training_Log.md#各-variant-状态)。本文不授权修改正在运行的实验，不增加必要研究模块。

## 1. 1500例如何使用

PI-CAI 公开开发集包含1500次检查、1476位患者，其中425例为临床显著前列腺癌阳性，1075例为良性或非临床显著癌阴性。2025年7月新增的 `Pooch25` 专家标注补齐了原先205例阳性，现可结合原有1295例标签使用全部1500例。旧教程中的专家标注子集与当前标签版本应区分。[官方标签说明](https://github.com/DIAGNijmegen/picai_labels#updates)

本仓库 manifest 已采用220例原有阳性专家标注与205例新增阳性专家标注，保留全部1075例阴性；对应统计与来源校验见 [manifest validation](../../data/metadata/picai_manifest_validation.json)。不能把新增标注当作 AI 伪标签，也不能把缺失标签静默视为阴性。

| 使用方式 | 建议与解释边界 |
|---|---|
| 全部1500例纳入开发数据池，按患者划分训练与评价集合 | 推荐；保留病例多样性与阴性监督 |
| 同一模型训练1500例，再用其中病例报告独立泛化性能 | 不成立；训练病例不能充当独立测试病例 |
| 只保留425例阳性训练 | 不作为当前默认方案；会移除阴性病例提供的假阳性监督，且缩窄任务范围 |
| 方法与参数冻结后，训练全部1500例并在独立外部集合测试 | 可作为未来最终模型方案；外部测试不得用于调参，先完成患者重叠与标签语义审计 |

## 2. 划分建议

官方基线提供患者无交叉的五折交叉验证划分；70%/10%/20%是部分论文的设计，并非 PI-CAI 的统一强制规则。[官方划分说明](https://github.com/DIAGNijmegen/picai_baseline#cross-validation-splits)、[Align then Refine 的实验设置](https://arxiv.org/html/2604.18713v1#S3)

当前项目采用固定患者级训练/验证划分，并按中心与患者阳性状态分层。同一患者的多个 study 保持在同一集合；具体病例列表与设计说明以 [冻结 split](../../data/splits/picai_train_val_split.json) 为准。

- 首轮机制实验沿用当前划分，不为匹配论文比例而重划分，不重新训练仅更换身份的共享 A2。
- 若使用验证集选择模型，应报告为内部验证证据，不能同时称为独立测试证据。
- 五折与独立测试能回答不同的泛化问题，但不自动将完整五折加入当前硕士研究的必要预算；执行范围由实验计划决定。
- 不根据某次运行的结果挑选更容易的 split。任何未来划分调整都需保持患者隔离，并同步检查 anatomy checkpoint、先验 provenance 与源 split，不能沿用不再匹配的先验。

## 3. 类别不平衡优先在训练采样层处理

病例数量不平衡与病灶体素稀少是两个不同问题。前者涉及训练抽取哪些病例，后者涉及 patch 是否覆盖病灶。当前 [positive-case sampler](../../src/zonal_reliability_fusion/sampling/positive_sampling.py) 已同时控制这两个环节：batch=2时，一个槽位从阳性训练病例抽取并强制围绕前景，另一个槽位从完整训练集合抽取。

因此原始约28.3%的阳性比例，不等于训练中阳性病例或前景 patch 的实际比例。空间增强仍可能改变病灶覆盖，不能宣称增强后的前景比例固定。

建议保持现有采样用于 B/C/D 融合对照。若未来有证据需要调整采样，只研究一种明确机制，使用独立 Trainer 身份与输出，不同时更换损失、patch、优化器和预处理。验证与测试保持固定病例集合及原生行为，不为展示效果做阳性富集或阴性删减。

## 4. 预处理建议与证据边界

公开资料支持多种可用方案，不能据此认定一种配置对所有 PI-CAI 病灶分割任务最优。官方预处理工具允许按病例或按数据集统一分辨率；官方轻量 U-Net 使用3.0×0.5×0.5 mm（z/y/x）与逐模态归一化，而 nnU-Net 根据 plans 配置处理数据。[官方预处理入口](https://github.com/DIAGNijmegen/picai_baseline#data-preprocessing)、[picai_prep](https://github.com/DIAGNijmegen/picai_prep)

| 环节 | 当前建议 | 需要确认的质量问题 |
|---|---|---|
| 标签来源与二值映射 | 保持当前专家标签组合 | 旧专家标签与 Pooch25 取值不同；映射需遵循来源，阴性标签应为空 |
| 模态网格 | 保持统一 T2W 物理网格的处理链 | 不只比 shape，还检查 spacing、origin、direction、病灶所在区域的信号覆盖 |
| 目标间距 | 首轮保持现有3.0×0.5×0.5 mm（z/y/x） | 小病灶重采样后体积、层数、独立病灶是否改变或消失 |
| MRI 强度归一化 | 首轮保持逐病例、逐模态 Z-score | 非有限值、异常强度、补零区域和统计范围是否影响归一化 |
| 裁剪 | 首轮保持非零区域裁剪 | 是否完整覆盖前列腺与病灶；不能把训练 patch 大小当成完整体积尺寸 |
| MRI 插值与存储类型 | 如实记录现有历史物化链，不就地重生数据 | 中间重采样与 uint16 转换可能引入量化；存在数值差异不等于已证实性能损失 |
| D 的解剖概率 | 沿用既有 MRI 网格与 predicted-prior 契约 | 概率不做 MRI 强度归一化；空间增强同步，强度增强仅作用于 MRI |

归一化方面，官方轻量 U-Net 使用0.5/99.5百分位截断后 Z-score；这可作为未来单独候选，但不能证明优于当前 nnU-Net 默认方案。任何训练和推理都应使用一致的处理约定。[官方 U-Net 说明](https://github.com/DIAGNijmegen/picai_baseline/blob/main/unet_baseline.md)、[nnU-Net 归一化说明](https://github.com/MIC-DKFZ/nnUNet/blob/master/documentation/explanation_normalization.md)

裁剪方面，官方轻量基线明确指出固定中心裁剪可能遇到偏心前列腺。因此不直接照抄更小的中心框。若未来研究预测腺体定位裁剪，须有安全边界与覆盖证据，推理定位只依赖该病例 MRI 的预测，不能使用 GT anatomy 或 GT lesion。[官方裁剪局限](https://github.com/DIAGNijmegen/picai_baseline/blob/main/unet_baseline.md#u-net---data-preparation)

配准方面，统一物理网格并不等于校正真实解剖错位或 DWI 畸变。相关研究发现形变配准改善了病灶对齐，但诊断性能的增量未达到统计显著，不能把配准视为必然改善病灶分割的步骤；该研究也不能证明两种方案等效。[MRI 配准研究](https://arxiv.org/abs/2404.09666)

## 5. 困难病例与错误数据分开处理

| 病例情况 | 建议处理 |
|---|---|
| 小病灶、低对比度、多病灶、困难背景、模型漏检或低 Dice | 保留；作为失败模式或分层分析对象 |
| 模态分辨率不同、但物理坐标合法且可正常重采样 | 保留；异网格本身不是数据错误 |
| 新增 Pooch25 专家标注 | 保留；不能仅依据标注批次推断质量差 |
| 某个 AI 腺体标签异常，但 MRI 与专家病灶标签可用 | 分别核查 anatomy 与 lesion 链路；不自动排除病灶病例 |
| 文件损坏、必要模态缺失、确认的图像/标签配错或无法修复的几何错误 | 优先追查来源与可修复性；确需排除时使用明确规则并保留证据 |
| 严重伪影、无法解释或无法可靠定位的疑似病例 | 需要独立质量评审；模型低分或高 loss 不能作为确认依据 |

官方已披露过 AI whole-gland 标签错误的个例，这说明腺体先验应单独核查，而不是把腺体标签错误等同于专家病灶标签错误。[官方标签资源说明](https://github.com/DIAGNijmegen/picai_labels#annotations-and-resources)

病例排除标准应独立于模型预测，并在应用前明确。记录病例ID、来源、原因、审查证据与影响；所有可比较模型保持相同评价范围。依据既有验证结果形成的较容易子集，只能标为事后探索，不能替代固定队列的正式结果。任何经确认的排除或数据修复均需评估对共享 A2 与未来模型可比性的影响，不静默改写 Dataset605/608 或历史产物。

## 6. 现有诊断能说明什么

已有 A2 结果表明，需要同时关注阳性覆盖和阴性假阳性，不能简单归因为阴性过多导致模型全部预测背景。具体数值和运行事实只见 [Training Log](../Training_Log.md) 与既有实验记录；这些是历史 VERSION=V1 共享对照的证据，不是 V2 性能结果。

已有 [九例数据链诊断](../../outputs/diagnostics/picai_case_chain_20261010T024730_612404Z/summary.json) 检查了选定漏检病例与对照的标签转换、几何覆盖和预处理对应关系。检查通过不证明全队列正确，也不证明处理已最优。

该诊断中，按目标间距计算的病灶体积约为物化参考体积的0.829～1.378倍，值得关注小病灶离散化与连通性。这个描述性范围不等于重采样 bug 或已经证实的性能损失，且仅代表选定九例。另有 [全验证集概率诊断](../../outputs/diagnostics/picai_probability_diagnostics_20261010T013859_953463Z/summary.json) 检查概率恢复与硬分割一致性；它不能替代全部病例的原始数据链检查。

评价继续遵循 [共享协议](../Evaluation_Protocol.md)。不依据论文中表面相近的 Dice 数字认定当前处理错误；病例范围、空值语义和聚合方式需要先对齐。

## 7. 优化优先级

| 优先级 | 建议 | 决策依据 |
|---|---|---|
| 最高 | 完成当前 B 的整例评价，与共享 A2 在固定队列比较 | 区分漏检、错位、覆盖不足与假阳性，避免只凭 patch pseudo Dice 判断 |
| 高 | 利用已有报告检查小病灶重采样、MRI 病灶区信号覆盖与真对齐 | 优先确认数据质量问题；现有检查范围之外的疑问明确保留 |
| 条件性 | 若确认预处理缺陷，设计一种最小的独立修复对照 | 单变量、相同病例与比较预算，不覆盖旧产物 |
| 暂不安排 | 全套五折、复杂配准、多个新采样/归一化/裁剪机制同时加入 | 当前融合研究无需一次承担全部工程与实验成本 |

运行状态以 Training Log 为准。若 B 尚在训练或自动验证，保持相关运行代码与输入不变；若已完成，则按实验计划逐步评价，不重复启动训练。本建议不触发任何真实数据处理、训练、验证或推理。长任务由用户运行，仍需显示进度并输出结构化完成统计。

采用某项建议时，方法契约归入 Method，预算与命令归入 Experiment Plan，评价定义归入 Evaluation Protocol，实际运行与代码变更分别记录到 Training Log 与 Development Log。本文件不扩展为另一份状态表或运行手册。
